# 工程基本功提升方案

## 核心目标

工程基本功的目标不是背更多知识点，也不是手写更多代码，而是形成一套稳定能力：

- 能把问题拆清楚
- 能写出可维护的代码
- 能判断方案是否合理
- 能定位系统问题
- 能在复杂场景下保证正确性
- 能审查 AI 生成的代码是否可靠

AI 时代，代码生成会越来越容易，但工程判断、系统理解、调试能力和质量兜底会更加重要。

## 训练主线

每个阶段都按下面这个循环训练：

1. 学一个基础概念
2. 写一个小实现
3. 用测试验证
4. 故意制造问题并调试
5. 写一篇短复盘

复盘重点回答：

- 我理解了什么
- 这个知识点解决什么问题
- 我踩了什么坑
- 有哪些边界条件
- 以后遇到类似问题该怎么判断

工程基本功不是“看懂了”，而是“遇到问题能解释、能定位、能修复”。

## 第一阶段：代码基本功

建议周期：2 到 4 周。

目标是写出清晰、可测试、可维护的代码。

重点训练：

- 函数拆分
- 命名
- 错误处理
- 单元测试
- 日志
- 边界条件
- 简单重构
- Git 基础操作

练习项目：

做一个命令行 TODO 工具。

功能要求：

- 新增任务
- 删除任务
- 修改任务
- 查询任务
- 标记完成
- 数据持久化到 JSON 或 SQLite
- 支持异常输入处理
- 编写 README

质量要求：

- 核心函数必须有测试
- 不把所有逻辑堆在一个文件里
- 每次改功能前先想清楚接口和数据结构
- 错误信息要能帮助定位问题

这一阶段要完成的转变是：从“代码能跑”升级到“代码别人能维护”。

## 第二阶段：数据结构与算法

建议周期：4 到 6 周。

目标不是刷题炫技，而是理解数据组织方式和问题建模方式。

重点掌握：

- 数组
- 链表
- 栈
- 队列
- 哈希表
- 树
- 堆
- 图
- 排序
- 二分
- 递归
- 动态规划基础
- 时间复杂度
- 空间复杂度

推荐顺序：

1. 数组和字符串
2. 哈希表
3. 双指针
4. 滑动窗口
5. 栈和队列
6. 二分查找
7. 树
8. 图
9. 动态规划入门

练习方式：

- 每天 1 到 2 道题
- 不追求数量
- 每道题都写题解
- 每道题都分析复杂度
- 每道题都列出边界条件

每道题复盘：

- 为什么使用这个数据结构
- 有没有更简单的方案
- 时间复杂度是多少
- 空间复杂度是多少
- 最容易错的边界条件是什么

这一阶段要训练的是：看到问题时，能判断它本质上需要什么数据结构。

## 第三阶段：数据库

建议周期：3 到 5 周。

目标是理解数据如何存储、查询、约束和保持一致性。

重点掌握：

- SQL 基础
- 表结构设计
- 主键和外键
- 索引
- 事务
- 隔离级别
- 锁
- 查询优化
- 数据建模

练习项目：

做一个博客系统或记账系统。

功能要求：

- 用户表
- 文章表或账单表
- 标签表
- 评论表或分类表
- 分页查询
- 条件筛选
- 搜索
- 事务操作

必须训练：

- 给查询加索引
- 使用 `EXPLAIN` 分析 SQL
- 故意写慢 SQL，然后优化
- 模拟并发更新余额或库存
- 观察事务隔离问题
- 解释表结构为什么这样设计

这一阶段要形成的能力是：看到业务数据后，能设计合理的数据模型，并知道查询慢在哪里。

### MySQL 快速掌握路线

如果目标是快速掌握 MySQL，不建议从零散知识点开始背，而是按“会用、会设计、会优化、会排查”的顺序推进。

建议周期：4 周。

#### 第 1 周：SQL 和表结构基础

目标：能独立建表、增删改查、写常见查询。

重点掌握：

- MySQL 安装和连接
- 数据库、表、字段、行的关系
- `CREATE TABLE`
- `INSERT`
- `UPDATE`
- `DELETE`
- `SELECT`
- `WHERE`
- `ORDER BY`
- `LIMIT`
- `GROUP BY`
- `HAVING`
- 常见字段类型：`INT`、`BIGINT`、`VARCHAR`、`TEXT`、`DECIMAL`、`DATETIME`
- `NULL` 和默认值
- 主键、自增、唯一约束

练习：

- 设计一个记账系统的表：用户表、账户表、账单表、分类表
- 写 30 条以上 SQL，包括新增、修改、删除、条件查询、分组统计
- 练习分页查询：按时间倒序查询账单列表

本周验收标准：

- 能不看教程写出基本 CRUD
- 能解释每个字段为什么选择这个类型
- 能说清楚主键、唯一约束、普通字段的区别

#### 第 2 周：表设计和关联查询

目标：能根据业务设计合理表结构，并写多表查询。

重点掌握：

- 一对一、一对多、多对多
- 外键的作用和取舍
- `JOIN`
- `LEFT JOIN`
- 子查询
- 聚合查询
- 表结构范式和适度反范式
- 金额字段不要用浮点数
- 时间字段统一规范
- 软删除字段
- 创建时间和更新时间

练习：

- 给记账系统增加标签表，支持一笔账单多个标签
- 查询某个用户每月支出总额
- 查询某个分类下最近 30 天账单
- 查询没有账单的分类
- 查询每个账户的余额变化记录

本周验收标准：

- 能画出简单 ER 图
- 能解释为什么要拆表或不拆表
- 能写出 3 张表以上的关联查询

#### 第 3 周：索引和查询优化

目标：知道 SQL 慢在哪里，并能用索引优化。

重点掌握：

- B+Tree 索引的基本原理
- 主键索引
- 普通索引
- 唯一索引
- 联合索引
- 最左前缀原则
- 覆盖索引
- 回表
- 索引失效场景
- `EXPLAIN`
- 慢查询日志

练习：

- 准备 10 万到 100 万条账单测试数据
- 对分页查询、时间范围查询、分类统计查询分别执行 `EXPLAIN`
- 故意不加索引，记录查询耗时
- 添加单列索引和联合索引，比较执行计划变化
- 故意写导致索引失效的 SQL，例如对字段使用函数、前置模糊匹配、类型不一致

本周验收标准：

- 能看懂 `EXPLAIN` 里的 `type`、`key`、`rows`、`Extra`
- 能根据查询条件设计联合索引
- 能解释为什么有些 SQL 加了索引也不快

#### 第 4 周：事务、锁和并发问题

目标：能处理真实业务里的数据一致性问题。

重点掌握：

- 事务的 ACID
- `BEGIN`
- `COMMIT`
- `ROLLBACK`
- 隔离级别
- 脏读、不可重复读、幻读
- 行锁
- 表锁
- 间隙锁
- 死锁
- 乐观锁
- 悲观锁
- 库存扣减
- 余额更新

练习：

- 实现转账：账户 A 扣款，账户 B 加款，必须在同一个事务里完成
- 模拟两个会话同时更新同一条余额
- 模拟库存扣减，保证库存不能扣成负数
- 故意制造死锁，观察 MySQL 报错
- 对比乐观锁和 `SELECT ... FOR UPDATE`

本周验收标准：

- 能解释什么时候必须使用事务
- 能说清楚并发更新为什么会丢数据
- 能写出不会超卖的库存扣减 SQL
- 能用两个 MySQL 会话复现锁等待问题

#### MySQL 必做小项目

建议做一个“记账系统后端”，不要只写 SQL 片段。

功能要求：

- 用户注册
- 创建账户
- 新增账单
- 修改账单
- 删除账单
- 按月份查询账单
- 按分类统计支出
- 按账户统计余额
- 标签筛选
- 分页查询
- 转账操作

数据库要求：

- 有建表 SQL
- 有初始化数据
- 有至少 20 条常用查询 SQL
- 有索引设计说明
- 有 `EXPLAIN` 优化记录
- 有事务案例
- 有并发问题复现记录

建议输出文档：

- `schema.sql`
- `seed.sql`
- `queries.sql`
- `index-design.md`
- `explain-analysis.md`
- `transaction-notes.md`

#### 每天训练安排

如果每天只有 1 小时：

- 20 分钟学一个概念
- 30 分钟写 SQL 或做实验
- 10 分钟记录结论

如果每天有 2 小时：

- 30 分钟学概念
- 70 分钟做项目或实验
- 20 分钟复盘和整理 SQL

不要只看 MySQL 视频。每天必须打开 MySQL 客户端写 SQL、造数据、看执行计划、复现错误。

#### 快速掌握 MySQL 的判断标准

达到下面标准，才算不是只会写简单 SQL：

- 能根据业务独立设计 5 到 8 张表
- 能写常见 CRUD、分页、统计、关联查询
- 能用 `EXPLAIN` 判断 SQL 有没有走索引
- 能根据查询场景设计联合索引
- 能解释事务隔离级别和锁等待现象
- 能处理余额、库存这类一致性问题
- 能写清楚表结构、索引和事务为什么这样设计

## 第四阶段：网络与后端基础

建议周期：4 到 6 周。

目标是理解一个请求从客户端到服务端再到数据库的完整链路。

重点掌握：

- HTTP
- DNS
- TCP 基础
- Cookie
- Session
- Token
- REST API
- HTTP 状态码
- 超时
- 重试
- 限流
- 鉴权
- CORS
- 缓存

练习项目：

写一个完整 API 服务。

功能要求：

- 注册
- 登录
- JWT 或 Session 鉴权
- CRUD 接口
- 分页
- 参数校验
- 统一错误响应
- 日志
- 简单限流
- 接口测试

额外训练：

- 用 `curl` 调接口
- 用 Postman 或 HTTPie 测试接口
- 故意让接口超时
- 故意传错参数
- 通过日志定位问题
- 区分客户端问题、服务端问题、数据库问题和配置问题

这一阶段要训练的是：请求出错时，知道该从哪里开始排查。

## 第五阶段：并发与系统稳定性

建议周期：4 到 8 周。

目标是理解系统在压力和异常情况下如何出问题，以及如何保证正确性。

重点掌握：

- 线程
- 协程
- 异步
- 锁
- 队列
- 竞态条件
- 死锁
- 幂等
- 重试
- 限流
- 熔断
- 缓存一致性

练习项目：

做一个秒杀或库存扣减小系统。

功能要求：

- 商品库存
- 下单
- 扣库存
- 防止超卖
- 请求限流
- 任务队列
- 失败重试
- 幂等处理

必须做压测：

- 使用 `wrk`、`ab`、`k6` 或类似工具
- 观察 QPS
- 观察响应时间
- 观察错误率
- 观察数据库压力
- 记录瓶颈在哪里

这一阶段非常关键。很多代码在单用户场景下能跑，但一到并发场景就会出现数据错误、性能下降或服务崩溃。

你要训练的是：系统在压力下仍然保持正确。

## 第六阶段：测试、调试与可观测性

建议长期训练。

这是最容易被低估的工程基本功。

重点掌握：

- 单元测试
- 集成测试
- 端到端测试
- Mock
- 日志设计
- 错误码
- Debugger
- 性能分析
- Profiling
- 监控指标

每个项目都要具备：

- 有测试
- 有日志
- 有错误处理
- 能复现问题
- 能定位问题
- 有基本文档

刻意练习：

- 修 bug 前先写失败测试
- 遇到异常先定位根因，再修改代码
- 慢接口用 profiler 分析
- 每次问题处理后写复盘
- 记录问题现象、排查路径、根因和修复方案

真正的工程能力，很大一部分体现在：别人说系统坏了，你能一步步把问题缩小到根因。

## 每天怎么练

如果每天有 1.5 小时：

- 30 分钟学习基础概念
- 45 分钟写代码或做实验
- 15 分钟写测试或调试
- 15 分钟写总结

如果每天有 3 小时：

- 45 分钟学习
- 90 分钟做项目
- 30 分钟测试或调试
- 15 分钟复盘

时间分配建议：

- 20% 看书、文档或课程
- 60% 写代码和实验
- 20% 测试、调试和复盘

不要只看视频。工程能力必须靠动手、出错、定位和修复来建立。

## 衡量标准

不要用“看了多少课”衡量学习效果，而要用下面这些问题衡量：

- 我能不能解释这段代码为什么这样设计
- 我能不能给它写测试
- 我能不能发现边界条件
- 我能不能定位性能瓶颈
- 我能不能处理并发问题
- 我能不能让别人接手维护
- 我能不能在 AI 生成代码后判断它有没有坑
- 我能不能把问题复现出来
- 我能不能写清楚修复方案

如果这些能力在提升，工程基本功就在提升。

## 最终判断

AI 时代，工程基本功不是过时了，而是变成了程序员的底层竞争力。

AI 可以帮你更快生成代码，但它不能替你承担系统质量、业务判断和长期维护责任。

真正值得训练的不是“如何让 AI 多写代码”，而是：

- 如何定义问题
- 如何判断方案
- 如何验证正确性
- 如何定位故障
- 如何交付可靠系统

这才是程序员在 AI 时代仍然有价值的核心原因。
