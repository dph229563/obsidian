# Codex 能做什么

Codex 是一个可以和你共享本地工作区的 AI 编程与协作助手。它不只是回答问题，也可以阅读项目、修改文件、运行命令、验证结果，并把工作整理成你可以继续使用的产物。

## 1. 代码与项目开发

Codex 可以帮助你完成日常开发中的很多任务：

- 阅读和理解现有代码库
- 查找文件、函数、配置和依赖关系
- 修复 bug
- 增加新功能
- 重构代码
- 编写脚本和工具
- 补充或调整测试
- 运行测试、构建、格式化、类型检查等命令
- 分析报错日志并定位问题
- 解释某段代码的作用
- 给出代码审查意见

适合的请求示例：

```text
帮我看看这个项目是怎么启动的
修复登录页按钮点击没有反应的问题
给这个函数补一组单元测试
帮我 review 最近的改动
```

## 2. 文件整理与文档生成

Codex 可以在当前目录中创建、修改和整理文件，例如：

- 生成 Markdown 文档
- 整理 README
- 写接口说明
- 写使用说明
- 写项目结构说明
- 生成开发计划或任务清单
- 总结代码库架构
- 整理会议记录、需求草稿或技术笔记

适合的请求示例：

```text
把这个项目的使用方法整理成 README
根据代码生成一份接口文档
把这些想法整理成 Markdown
```

## 3. 前端页面与应用制作

如果项目包含前端，Codex 可以帮助你：

- 创建页面和组件
- 调整布局、样式和交互
- 接入图标、表单、弹窗、菜单、标签页等 UI 元素
- 修复响应式布局问题
- 启动本地开发服务器
- 用浏览器检查页面效果
- 根据截图或描述优化界面

适合的请求示例：

```text
帮我做一个待办事项页面
把这个页面改得更像后台管理系统
修复移动端文字重叠的问题
启动项目并告诉我访问地址
```

## 4. 调试与验证

Codex 可以在本地执行命令来验证问题是否解决：

- 查看终端输出
- 运行测试
- 运行构建
- 启动服务
- 检查依赖
- 分析错误信息
- 对比改动前后的行为

如果某些命令需要联网、安装依赖、访问受限目录或执行高权限操作，Codex 会请求你的许可。

## 5. Git 与变更管理

Codex 可以辅助你理解和管理代码变更：

- 查看 Git 状态
- 查看 diff
- 总结本次改动
- 帮你准备 commit message
- 分析某个提交
- 做代码 review

Codex 会避免撤销你已有的改动，除非你明确要求。

适合的请求示例：

```text
帮我看一下当前 git diff
给这次改动写一个 commit message
review 这个分支有没有明显问题
```

## 6. 数据、文档、表格和演示稿

在支持的环境中，Codex 也可以处理一些办公类文件：

- 创建或修改 Word 文档
- 创建或分析 Excel/CSV 表格
- 制作 PowerPoint 演示稿
- 渲染并检查文档、表格或幻灯片效果

适合的请求示例：

```text
帮我把这个 CSV 汇总成一张表
做一份项目汇报 PPT
把这份说明整理成 Word 文档
```

## 7. 图片与视觉素材

当任务需要视觉资源时，Codex 可以帮助你：

- 生成图片素材
- 编辑或改造已有图片
- 制作前端所需的视觉资产
- 检查本地图片效果
- 为页面或应用选择合适的视觉方向

适合的请求示例：

```text
帮我生成一张产品宣传图
把这个图做成透明背景
给这个小游戏做几张像素风素材
```

## 8. 联网查询与最新信息

当问题涉及最新信息、价格、版本、法规、新闻、公司职位、产品规格等可能变化的内容时，Codex 可以联网核查，并在回答中给出来源链接。

适合的请求示例：

```text
查一下某个库最新版本怎么用
帮我确认 OpenAI API 最新文档
找一下这个产品目前的官方规格
```

## 9. 自动化与提醒

在支持的应用环境中，Codex 可以帮助创建、查看、更新或删除自动化任务，例如：

- 定时提醒
- 周期性检查
- 后续跟进
- 监控某些状态变化

适合的请求示例：

```text
明天下午提醒我检查部署结果
每周一提醒我更新项目进度
```

## 10. 你可以怎样和 Codex 协作

你可以用很自然的方式提出需求。Codex 会根据任务复杂度决定是直接动手，还是先确认关键细节。

常见协作方式：

- 直接下达任务：`帮我修复这个报错`
- 提供目标：`我要做一个简单的库存管理页面`
- 要求解释：`这段代码为什么这样写`
- 要求审查：`帮我 review 一下`
- 要求输出文件：`整理成 Markdown 放到当前目录`
- 要求验证：`改完后帮我跑测试`

## 11. Codex 做事时的原则

Codex 在处理项目时通常会遵循这些原则：

- 先理解现有代码，再修改
- 尽量沿用项目已有风格
- 控制改动范围，避免无关重构
- 不随意覆盖或撤销你的文件
- 修改后尽量验证
- 对不确定或高风险操作先请求确认
- 对失败的测试、命令或限制如实说明

## 12. 使用小建议

为了让 Codex 更高效，你可以尽量说明：

- 你希望最终得到什么结果
- 哪些文件或页面最相关
- 是否需要运行测试或启动项目
- 是否有特定技术栈、风格或格式要求
- 输出文件名或保存位置

例如：

```text
请阅读当前项目，整理一份架构说明，输出为 docs/architecture.md
修复前端登录页的样式问题，完成后启动本地服务并截图检查
分析当前报错，只解释原因，先不要改代码
```

## 总结

Codex 可以把“问答助手”和“本地开发协作者”结合起来：它能读项目、写文件、改代码、跑命令、查资料、做文档、调页面、处理表格和演示稿。最适合交给 Codex 的任务，是那些需要理解上下文、动手修改、并验证结果的工作。
